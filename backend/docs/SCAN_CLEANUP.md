# 扫盘清理设计

本文描述扫盘"缺失确认与清理"阶段的设计。它既要避免失败目录造成误删，也要让存在性完整的扫描结果立即生效，不让已确认不存在的视频无谓多保留一轮。

本文中的后端路径均相对 `backend/`：`internal/scanner`（发现与对账）、`internal/catalog/scan_presence.go`（缺失计数）、`cmd/server/scan.go`（扫盘编排与清理）、`internal/api/admin_drive_operations.go`（跳过目录保存接口）。前端相关文件为 `src/admin/drive/SkipDirsPanel.tsx`。

## 1. 改造前的现状与根因

### 1.1 原有行为

原有扫盘分四步：发现（只读递归，生成 `Snapshot`）、对账（写 Catalog）、缺失确认与清理、派生任务投递。

当时清理的准入条件是 `Snapshot.Complete()`，即发现阶段没有任何目录级 `Issue`。旧的 `cleanupScanSnapshot` 在快照不完整时直接整盘跳过，日志为：

```
[cleanup] skip stale cleanup for drive=... discovery had N directory errors
```

触发这个旧闸门的只有子目录 `List` 失败。对账阶段的单文件写库错误记在 `Result.Issues`，不影响快照完整性，也不影响旧清理逻辑。根目录列举失败会让整轮扫描在对账前终止，属于另一条路径，本文不改。

### 1.2 为什么当初要一刀切

旧的 `ConfirmMissingDriveFiles` 在全盘扫描模式下把该网盘的所有记录都视为可判缺失，只有局部扫描才检查记录的父目录是否在本轮访问集合中。某个子目录打不开时，它下面的文件不在 `SeenFileIDs` 里；若照常推进计数，同一目录连续两轮打不开，整棵子树的库记录和本地封面预览都会被删。闸门是必要的，但它把"哪些目录真的被枚举了"压缩成了一个布尔值。

### 1.3 根因

1. `discoverDir` 在调用 `List` 之前就把目录写入 `VisitedDirIDs`。"访问过"的实际含义是"尝试过"，打不开的目录看起来也像枚举成功，它的直接子文件在局部模式下也会被判缺失。
2. 打不开的目录 ID 已经记录在 `Issue.DirID` 中，但下游没有任何逻辑用它圈出不可达子树。
3. 视频表只存直接 `parent_id`，没有目录树，深层后代无法回答"是否在某个失败目录之下"。这正是当初退回全有全无的原因。

## 2. 目标与非目标

目标：

- 一个目录打不开只影响它自己的子树，其余部分照常推进缺失计数与删除。
- 整个文件夹被删除的情况，不需要等待"零错误的晚上"也能正常老化。
- 扫描根目录缩小或切换后，旧范围记录能在当前配置范围完整扫描后退出媒体库。
- 跳过目录下的视频退出媒体库不再依赖缺失计数，而是作为管理员的策略决定单独处理，且有一段可反悔的缓冲期。
- 已部署实例升级后自动补齐历史积压，不需要人工操作。
- 策略清理的局部数据库或文件错误不阻断后续缺失清理和派生任务。
- 网盘限流在失败目录固定冷却 10 分钟后重试；整个网盘的一次任务最多冷却重试 3 次，之后结束本轮。单次请求超时有限重试后只把对应目录记入 F。

非目标：

- 不删除网盘上的源文件。
- 不引入独立的目录树表。
- 任务被管理员停止、服务关闭等主动取消时，仍立即结束本轮扫盘。
- 爬虫盘与站内上传盘仍不参与本流程。

## 3. 核心概念

### 3.1 三个目录集合

发现阶段结束后，快照给出三个互不重叠的目录集合：

| 集合 | 含义 | 来源 |
|---|---|---|
| E 枚举成功 | `List` 成功返回的目录 | 递归遍历 |
| F 打开失败 | 尝试 `List` 但失败的目录（非致命错误） | 原 `Issue.DirID` |
| X 策略排除 | 命中配置跳过目录，未进入 | 原 `ExcludedDirIDs` |

一个被枚举成功的目录列出的每个子目录，一定落在 E、F、X 之一。这个性质是后面推断"目录已不存在"的依据。

### 3.2 祖先目录链

每条视频记录新增祖先目录链：从扫描起点到直接父目录的目录 ID 序列，含两端。发现阶段递归时把链一路传下去，对账阶段写入新记录，位置变化时随现有的元数据同步路径一起更新。

它是对现有 `parent_id` / `dir_name` 的补全，属于同一类信息，由同一条对账路径维护。

升级前的旧记录没有链。规则统一使用"有效链"：有存储链就用存储链；否则若 `parent_id` 非空，视为单元素链 `[parent_id]`；否则为空链。

### 3.3 两种清理

| | 缺失清理 | 策略清理 |
|---|---|---|
| 回答的问题 | 文件是不是不在了 | 管理员还要不要这个目录 |
| 判断依据 | 本轮观察结果 + 祖先链 | 跳过目录配置 |
| 是否需要多次确认 | 存在性完整时直接清理；目录发现不完整时连续两次 | 否，配置即决定 |
| 执行时机 | 每次扫盘，对账和策略清理之后 | 对账之后；配置变化或仍有待补课目录时实做 |
| 删除方式 | 共用同一套删除函数 | 共用同一套删除函数 |

删除函数的行为与现在一致：删本地预览、封面、帧签名，删 Catalog 记录及关联，不写墓碑，不碰网盘。不写墓碑意味着取消跳过后视频会在下次扫盘重新入库，ID 不变，但手动标签和播放记录不会恢复。

## 4. 扫盘流程

```mermaid
flowchart LR
    A["准入<br/>任务上下文 / 互斥"] --> B["挂载与配置"]
    B --> C["发现<br/>只读递归，产出 E / F / X 与祖先链"]
    C --> D["对账<br/>写入与更新记录"]
    D --> E["策略清理<br/>使用最新祖先链"]
    E --> F["缺失清理<br/>按目录集合逐条判断"]
    F --> G["派生任务投递"]
```

缺失清理不再有"快照不完整则整盘跳过"的闸门。策略清理必须位于对账之后：文件从跳过目录移到普通目录时，对账先把持久化祖先链改成新位置，策略清理不会再按旧链把它删除后重新入库。

`SeenFileIDs` 还作为策略清理的第二道保护。即使某条已发现视频的祖先链更新失败，它也不会在本轮被旧链误删。策略清理结束后才进入普通缺失清理。

## 5. 扫描器改动（`internal/scanner`）

### 5.1 发现阶段

- 目录只在 `List` 成功后进入 E。环检测另用一个内部的"已尝试"集合，失败目录本轮不再重试进入。
- `List` 遇到请求超时、连接重置或 EOF 等临时传输错误时，最多原地重试两次。重试前分别等待 1 秒、3 秒，并增加最多 25% 的随机延迟；等待可被任务取消打断。仍失败则目录进入 F，只记录一个目录级 `Issue`。
- `List` 遇到网盘限流时固定等待 10 分钟，然后重试同一目录；等待可被管理员停止任务打断。策略补课和正常发现共享整轮预算，最多冷却重试 3 次，第 4 次限流直接返回“预算耗尽”。驱动内部自带的限流策略不在此预算内。
- 命中跳过配置的目录进入 X，不递归。原有的按目录名跳过 `previews` 的规则一并删除，见 5.4。
- 递归参数增加祖先链；每个 `File` 携带自己的链。
- 扫盘任务自身的 context 被取消时立即终止整轮。正常发现用尽 3 次限流预算时无法形成完整结果，本轮在对账前结束；对账后的策略补课用尽预算时只结束策略步骤，已形成的快照仍可进入缺失清理。某次网盘请求返回的超时不是任务取消；根目录在重试后仍打不开时因为无法形成快照，本轮仍会在对账前结束。

`Snapshot` 字段包括：`EnumeratedDirIDs`、`FailedDirIDs`、`ExcludedDirIDs`、`Files`、`SeenFileIDs`、`Issues`、`StartDirID`。`PresenceAuthoritative()` 表示当前配置的扫描起点已进入 E，且没有 F 或发现阶段 Issue；它描述的是"当前配置范围是否完整"，不再用"是否从物理网盘根开始"代替这个概念。

鉴权、权限、证书校验等非临时传输错误仍按目录进入 F，不额外重试；后续轮次会自然重试该目录。

传输错误分类、次数上限和退避间隔由 `internal/readretry` 共享。扫描器负责后台列目录重试；管理后台的目录浏览入口独立使用同一策略，并为请求和等待设置合计 45 秒的期限。115 文件信息与下载链接读取由其 SDK 读取客户端负责重试，沿用 15 秒的总预算；不在驱动 `List` 或写操作外叠加这套传输重试。

### 5.2 对账阶段

- 新记录写入祖先链。
- 已有记录比较链是否变化，变化则通过 `VideoMetaPatch` 一并更新，与现有 `ParentID` / `DirName` 的处理方式相同。

### 5.3 `Discover` 的复用

`Scanner.Discover(ctx, startDirID)` 已导出。策略清理的老数据补课以跳过目录为起点调用它，得到该目录下所有枚举成功的子目录。调用时使用同一份跳过配置，因此嵌套在内的其他跳过目录会被排除，在各自的迭代中处理。

### 5.4 删除 `previews` 目录名规则

现有扫描器会跳过任何名为 `previews` 的目录。这条规则来自最初版本：当时生成的预览片段会上传回网盘的 `previews/` 目录，扫描器跳过它以免把自己生成的片段扫成视频。该功能已在 2026 年 5 月 14 日移除（提交 `164d96c`，"keep previews local only"），预览此后只存本地 `data/previews/`。规则本身没有随之删除。

本设计删除这条规则，不做任何替代处理。名为 `previews` 的目录就是一个普通目录，正常进入、正常入库、正常参与缺失清理。理由：它服务的功能已不存在；它会静默跳过用户网盘上任何同名目录，后台不可见、配置里也没有。

删除后 X 集合只有一个来源，缺失清理对 X 可以完全不处理，两条清理路径不再交叉。

## 6. 数据模型

### 6.1 `videos`

新增列 `ancestor_dir_ids TEXT NOT NULL DEFAULT ''`，内容为 JSON 数组。目录 ID 在 WebDAV、本地盘等驱动下可能包含 `/`，因此不用分隔符拼接。查询"链中包含某目录"使用 `json_each`，当前使用的 modernc.org/sqlite 内置 JSON1。

需要同步维护的位置：`addColumnIfMissing` 迁移；`currentVideoColumnNames` 列清单，否则 schema 重建会丢掉该列；`Video` 结构与读写语句；`VideoMetaPatch` 增加 `AncestorDirIDs` 与对应的 Set 标记。备份与恢复按表整体处理，新列随表走。

### 6.2 策略清理进度

`drives` 新增一列记录精确策略清理进度：

| 列 | 含义 |
|---|---|
| `skip_cleanup_dir_ids TEXT` | 上次策略清理完成时使用的跳过名单，JSON 数组。NULL 表示从未执行 |

另建 `drive_skip_cleanup_legacy_dirs` 状态表，以 `(drive_id, dir_id)` 为主键记录每个跳过目录是否已完成老数据补课。一个目录永久打不开时，只重试它自己，不会让其它已完成目录每晚重复遍历。

### 6.3 `drive_scan_misses`

表结构不变，但只在目录发现不完整的保护模式下写入：符合缺失条件的记录累计两次。存在性完整模式不新增标记，并清除候选记录可能遗留的旧标记。删除视频时仍同时删除对应计数行；现有的孤儿清理语句继续作为兜底。

## 7. 缺失清理规则

入口是 `EvaluateMissingDriveFiles`，接收携带 E、F、X、`PresenceAuthoritative` 和 `ProtectUnlocated` 的范围描述，以及显式的清理模式。

编排层只根据存在性证据选择模式：扫描起点成功枚举，且正常发现的 F 与 `Snapshot.Issues` 都为空时，使用立即模式；否则使用连续两次确认模式。X 是主动排除，不是错误。`Result.Issues` 和 `Stats.Errors` 还包含标签匹配、重复检查、元数据更新、写库等对账错误，这些错误不会改变发现阶段已经形成的 E/F/X 与 `SeenFileIDs`，因此不参与模式选择。策略清理错误同样不把整盘降级，而是在必要时仅保护无法定位的旧记录。根目录列举或对账发生致命错误时整轮直接结束，不进入任一清理模式。

对该网盘的每条记录：

- 本轮看到了：清零计数。
- 没看到：取有效链 `[d0, d1, ..., dk]`，从 `d0` 开始找第一个不在 E 中的目录，记为 `di`。按下表处理。

| 情况 | 判定 | 动作 |
|---|---|---|
| 链上所有目录都在 E | 父目录完好，文件本身不在了 | 进入缺失候选集 |
| `i = 0`，链的起点就不在 E | 旧链不属于当前扫描起点，或无法定位 | 当前配置范围完整时进入候选集，否则保护 |
| `di` 在 F | 所在子树本轮不可达 | 保护，不计数 |
| `di` 在 X | 所在目录是配置的跳过目录 | 不处理，由策略清理负责 |
| `di` 不在 E、F、X 任何一个 | `d(i-1)` 枚举成功却没有列出 `di`，该目录已不存在 | 进入缺失候选集 |

兜底规则：`i = 0` 或有效链为空的记录，在当前配置范围具备权威性时进入缺失候选集。这里的"完整"针对配置范围，而不是物理网盘根；所以根目录缩小或切换后，旧范围记录会在一次完整扫描后被清理。如果当前范围存在 F，这类记录可能已经移动进失败子树，继续保护。

关于 `di` 在 X 的说明：配置跳过目录下的记录已在对账之后由策略清理处理，正常情况下不会走到这里。若精确策略清理失败，漏删记录仍由 X 保护、不计数，下次扫盘会自动重跑。

老版本的空祖先链记录还需要策略补课。只要任一待补课跳过目录未完成，本轮就设置 `ProtectUnlocated`，仅保护 `i = 0` 和空链记录；已经能由 E/F/X 定位的其他记录不受影响。这样不会退回"策略清理一错，整盘都等待两次"的粗粒度判断。

立即模式把候选记录直接交给共用删除函数，不新增缺失标记；如果候选已有历史标记，同时清除。保护模式才把候选的连续缺失计数加一，达到两次后交给共用删除函数。本轮看到的文件在两种模式下都会清除旧标记。不在本轮有效范围内以及位于 F、X 下的记录既不删除，也不推进标记。

## 8. 策略清理

### 8.1 触发与缓冲期

唯一触发点是扫盘中的对账之后。保存跳过目录的接口只写配置，不排任务，不触发扫描，与现有接口约定一致。

保存与下次扫盘之间形成一段缓冲期。用户在这期间取消刚设置的跳过目录，目录已不在名单中，策略清理不会匹配到任何记录，什么都不删。手动点击"重新扫描"会立即结束缓冲期，这是用户的主动操作。

前端在跳过目录面板显示一行提示：跳过目录下的视频会在下次扫盘时从媒体库移除，在此之前取消即可保留；取消跳过后视频会重新入库，但手动标签和播放记录不会恢复。不弹确认框。

### 8.2 执行步骤

爬虫盘和站内上传盘直接返回。其余网盘：

0. 比较当前跳过名单与 `skip_cleanup_dir_ids`，并从 `drive_skip_cleanup_legacy_dirs` 找出当前名单中尚未完成补课的目录。名单相同且没有待补课目录时直接返回。
1. 精确清理。查出有效链与当前跳过名单有交集的所有记录，排除本轮 `SeenFileIDs` 后交给共用删除函数。纯数据库操作，不访问网盘。旧记录中直接位于跳过目录下的，因有效链退化为 `[parent_id]`，也在这一步处理。
2. 老数据补课。先查询该网盘是否还有 `ancestor_dir_ids = ''` 的旧记录；一条都没有时，直接把当前待处理目录逐个标记完成，不访问网盘。仍有旧记录时，只对尚未完成的跳过目录调用 `Discover`，取其枚举成功的子目录集合加上自身，排除本轮已看到的视频，再删除 `parent_id` 落在其中的记录。某个目录完整遍历并完成删除后立即单独记录完成；遍历不完整则只保留该目录待重试，已经找到的记录照删。补课与前面的正常发现共用“10 分钟 × 3 次”的限流预算；预算耗尽时结束策略清理，但不丢弃已经完成的正常发现结果。
3. 第 1 步成功后，把当前名单写入 `skip_cleanup_dir_ids`。第 1 步失败则不写入，下次扫盘自动重跑。第 2 步是否完整不影响这一步。
4. 策略清理中的查询、删除或进度写入等非取消错误统一记录 `[skip-cleanup]` 日志，随后继续缺失清理和派生任务；X 下未删成功的记录仍受缺失清理保护。

日志前缀使用 `[skip-cleanup]`，与缺失清理的 `[cleanup]` 区分。

### 8.3 为什么精确清理必须不依赖遍历

很多人跳过一个目录，正是因为它经常打不开。若清理只能靠进入目录遍历，这些记录永远删不掉。祖先链是在该目录还能正常扫描时记下的，精确清理据此工作，不需要再进入目录。

### 8.4 取消跳过

从名单中移除后，本轮发现阶段会正常进入该目录，对账先更新或重新写入视频；之后策略清理使用新名单，不会匹配该目录，并更新记录名单。

## 9. 升级与老数据

升级只新增列，没有数据回填。旧记录的链为空，按来源分三类：

| 旧记录状态 | 处理 |
|---|---|
| 仍在网盘的可扫描区域 | 升级后第一次扫盘看到它，对账时补上链 |
| 位于跳过目录之下 | 直接子级由策略清理第 1 步处理；更深层由第 2 步补课一次处理 |
| 已从当前配置范围消失 | 当前配置范围完成一次存在性完整的扫描后，按兜底规则直接清理 |

升级后第一次扫盘时 `skip_cleanup_dir_ids` 为 NULL、逐目录补课状态为空。没有空祖先链旧记录的网盘会直接把当前跳过目录标记完成；有旧记录时只遍历尚未完成的目录，并逐个保存成功进度。

## 10. 边界与已知取舍

- 文件被移动到一个目录，而该目录连续两轮都打不开：旧位置的父目录枚举成功但没有该文件，会被判为消失并在第二轮删除；目录恢复后重新入库，手动标签和播放记录丢失。现有的全盘拦截不会遇到此情况，因为它什么都不删。这是接受"在有错误的轮次也推进清理"的代价，需要移动与连续两次失败同时发生。
- "存在性完整"只能依据驱动显式返回的结果判断。如果上游以成功响应静默返回空列表、漏页或截断数据，系统会把它视为完整快照并立即清理；因此驱动必须严格校验分页并把异常返回为错误。
- 扫描起点缩小或切换：旧链以旧起点开头，`i = 0`；当前配置范围完整时直接清理，范围内有 F 时保护，避免误删刚移动进失败子树但尚未被看到的文件。
- 目录 ID 为路径的驱动（WebDAV、本地盘）：重命名目录等价于删除加新增，旧记录按普通缺失老化，新记录重新入库。与今天一致。
- 策略清理第 1 步中途失败：名单不会被记录，下次扫盘重跑第 1 步补删；有祖先链的记录由 X 保护，补课未完成时无法定位的旧记录由 `ProtectUnlocated` 保护。
- 并发：策略清理与缺失清理都在同一个网盘任务门内运行；涉及本地资产与 Catalog 联动删除的短临界区受 `persistence` 读锁保护。扫盘期间保存的跳过目录按现有租约机制延后生效，下次扫盘可见。

## 11. 不变的事项

- 目录发现不完整时仍使用连续两次缺失确认，阈值为 2。
- 任务 context 被取消时，在任何后续对账写入前终止整轮。
- 爬虫盘与站内上传盘不参与缺失清理和策略清理。
- 不删除网盘源文件，删除不写墓碑。
- 手动扫盘与夜间流水线共享互斥与停止机制。
